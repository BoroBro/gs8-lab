# Приборка и HUD на GAC GS8: архитектура, возможности, план

> Рабочие заметки. ГУ 2023, прошивка V3.1-20230925, Android 9.

## HUD (проекция на стекло)

ГУ **не управляет HUD**. `MeterController/bridge/HudBus.java` — пустая заглушка,
глобальный поиск (hud / head-up / windshield) по всем модулям пуст. HUD рисует
кластер/ЭБУ машины и зеркалит своё содержимое. До стекла долетает только то,
что ГУ отдало на приборку (косвенно). Отдельного канала «ГУ → HUD» нет.

## Приборка: архитектура

Мост — приложение **`MeterController`**. Категорийные «автобусы» шлют данные в
кластер битовыми CAN-сигналами:

    источник (навигатор/медиа/телефон)
      -> MeterController: MapBus / MediaBus / PhoneBus / PanelSourceBus / SystemBus
         (HudBus = заглушка)
      -> MeterCanBus.sendModule33E/339/38F/351(битовое_смещение, длина, значение)
      -> CAN-кадры 0x33E, 0x339, 0x38F, 0x351
      -> MCU кластера рисует виджеты

Каждый вызов упаковывает значение в конкретные биты конкретного кадра —
у кластера фиксированный «протокол приборки», ГУ заполняет поля.

## Логика навигации

- Штатный навигатор **Karta/NDrive** (`com.kartatech.kartaauto.roctec.gac60ui`,
  активность `com.ndrive.mi9.Cor3MapActivity`) поднимает AIDL
  `com.ndrive.common.services.aidl.INaviInterface` / `INaviStateProvider`.
- Библиотека **`navi_client`** (в MeterController и лаунчере) биндится к нему,
  регистрирует колбэк, получает `DestinationInfo` (дистанция до цели, ETA) и
  `InstructionInfo` (манёвр, дистанция до манёвра).
- `MapProcessor` переводит колбэки в вызовы `MapBus` -> CAN. Гейт — свойство
  `sys.gis_status` и `isNavigationRunning()`.
- Сторонние/проекционные навигаторы (AMap/AutoNavi, CarLife, CLD, LuoTe) идут
  через broadcast-обработчики ZHLogic — в основном статус и приглушение музыки.

Важно: **Google Maps в Android Auto/HUR на приборку не идёт** — он не штатный
навигатор и не шлёт AUTONAVI-broadcast.

## Что ГУ умеет послать на приборку

- **Навигация:** статус; иконка манёвра TBT (фикс. набор, `MapIcon.getTBTValue`);
  иконка кольца; дистанция до манёвра + прогресс-бар + единицы; дистанция до цели
  + единицы; ETA часы/минуты; флаг смены дороги; **название дороги текстом**
  (многокадровый «character transfer» на 0x38F); статус GPS-сигнала.
- **Медиа:** имя источника, название трека, текущее/полное время, радио AM/FM.
- **Телефон:** статус/тип звонка, имя абонента, номер, длительность.
- **Источник/система:** индикатор источника, радио-действия, поиск станций, питание.

## Как увидеть текущую реализацию (диагностика)

1. Проверить навигатор: `adb shell pm list packages | findstr /i "kartatech ndrive"`.
2. Запустить: `adb shell am start -n com.kartatech.kartaauto.roctec.gac60ui/com.ndrive.mi9.Cor3MapActivity`, задать маршрут.
3. Смотреть вывод в кластер: `adb logcat -s MapBus:* MapProcessor:*` — пойдут
   `sendNaviIconTBT`, `sendNaviDist`, `sendNaviDestDistInfo`, `sendNaviMinitue`.
   Идут логи, а приборка пуста -> включать отображение нави в настройках.
   Логов нет -> ведение не стартовало / не тот навигатор.

## План эксперимента: навигация Android Auto -> приборка

Цель: показать повороты Google Maps (через HUR) на штатной приборке (и, через неё,
на HUD).

Шаг 0 (диагностика точки входа). Выяснить, чем кормится кластер:
- Подтвердить логами `MapBus`, что штатный навигатор его двигает (база для сравнения).
- Проверить, двигает ли кластер **AUTONAVI-broadcast**: послать тестовый
  `AUTONAVI_STANDARD_BROADCAST_SEND` с полями нави и смотреть, зашевелился ли
  `MapBus`. Если да — путь через broadcast рабочий. Если нет — кластер слушает
  только AIDL Karta (сложнее).

Шаг 1. Приёмник в gs8-lab: слушать `NavigationUpdateIntent` HUR
(`com.andrerinas.headunitrevived.NAVIGATION_UPDATE`) — дистанция, манёвр, дорога, ETA.

Шаг 2. Конвертер: из данных HUR собрать `AUTONAVI_STANDARD_BROADCAST_SEND`
(KEY_TYPE полей нави, маппинг манёвров AA -> коды AMap -> иконки кластера) и слать.

Шаг 3. Проверка на приборке/HUD. Маппинг иконок подогнать по `MapIcon.getTBTValue`.

Варианты, если broadcast не доходит до кластера:
- Прямая отправка CAN-кадров 0x33E/0x339/0x38F — нужен привилегированный доступ к
  CAN-TX (MCU HAL), рискованно, уровень системы.
- Подмена AIDL штатного навигатора — нельзя подделать пакет `com.kartatech...`.

CAN-кадры приборки: 0x33E, 0x339, 0x38F (нави/медиа/телефон/текст), 0x351 (источник).
